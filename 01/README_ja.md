# Camp Window Finder

キャンプ場と複数の候補日を指定し、単なる「晴れ / 雨」ではなく、キャンプ中の行動ごとに天候を評価する静的Webアプリです。

## できること

- キャンプ場・施設名検索
- 緯度 / 経度の直接指定
- 複数の2泊3日などの日程を比較
- 総合キャンプ指数 0〜100
- 設営しやすさ / 焚き火 / 夜の快適性 / 撤収を個別採点
- 気温、降水量、風速、突風、湿度の時間別表示
- 露点差を使った結露リスク
- 降水・湿度・日射による「テント乾燥開始目安」
- 結果のテキストコピー
- 結果のJSON保存
- 16日より先は「過去5年同時期傾向」に自動切替
- PWA用manifest / Service Worker付き（画面資産のみキャッシュ）

## 起動

### Windows
`start.bat` をダブルクリックしてください。

Pythonが使える環境なら `http://localhost:8000/` を開いて起動します。

### 手動
```bash
python -m http.server 8000
```

その後ブラウザで `http://localhost:8000/` を開きます。

`index.html` の直接オープンでも動くブラウザはありますが、Service Workerや一部のブラウザ制限を避けるためローカルサーバ起動を推奨します。

## データ源

### 天気
Open-Meteo Forecast API / Historical Weather API

取得項目:
- temperature_2m
- apparent_temperature
- relative_humidity_2m
- dew_point_2m
- precipitation
- precipitation_probability（実予報のみ）
- weather_code
- wind_speed_10m
- wind_gusts_10m
- shortwave_radiation

通常のForecast APIは最大16日先までです。そのため、それより先の候補日は実予報として扱わず、過去5年の同時期データから時間別の代表値を作って「参考傾向」と表示します。

### 場所検索
OpenStreetMap Nominatimの公開検索を、ユーザーが「場所を検索」ボタンを押した時だけ使います。

実装上の配慮:
- オートコンプリート検索をしない
- 1秒未満の連続リクエストを避ける
- 同じ検索語の結果を localStorage にキャッシュ
- 画面下部にOpenStreetMap attributionを表示
- 施設名で見つからない場合はOpen-Meteo GeoNames検索へフォールバック
- 緯度経度の直接入力も可能

公開サイトのアクセス量が増える場合は、Nominatimの公開サーバをそのまま大量利用せず、自前プロキシ/キャッシュや別のジオコーディングサービスへの切替を推奨します。

## 指数の考え方

### 設営しやすさ
初日 13:00〜16:00 を対象。
雨、風、突風、気温を評価します。

### 焚き火
17:00〜22:00 を対象。
雨、風、突風を特に強く減点します。
実際の焚き火可否はキャンプ場ルール・乾燥注意報等を優先してください。

### 夜の快適性
21:00〜翌07:00 を対象。
最低気温、湿度、降水、強い突風を評価します。

### 撤収
最終日 07:00〜11:00 を対象。
降水、湿度、風、日射を評価します。

### 総合
- 設営 30%
- 焚き火 25%
- 夜 20%
- 撤収 25%

この配点と閾値は `js/scoring.js` で変更できます。

## 重要

この指数は意思決定補助用の独自指標です。山間部や林間サイトでは、気象モデルの格子値と現地条件に差が出ます。
強風・大雨・雷・警報・道路状況・キャンプ場からの案内は、必ず公式情報を優先してください。
